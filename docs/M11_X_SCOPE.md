# M11-X — Native capture and manual typing

Baseline: `83a88bc2a80c8b4c03cd93bba540dafd57850bc1`, merged M10-R #25/#26. Local v1.0.2 and all existing tags/releases are preserved. This is a development candidate, not a Remote release. M11-R web history remains deferred.

## Delivered design

- WGC `IGraphicsCaptureItemInterop::CreateForMonitor`, free-threaded frame pool, D3D11 staging readback and PNG encoding inside the Rust shell. Physical frame dimensions avoid logical-coordinate DPI scaling; 64 MP cap covers ordinary 4K. The configured display device name is re-resolved each capture; a removed display refuses rather than capturing another monitor. Empty selection intentionally follows the current primary display. SDR BGRA8 output; HDR tone mapping is not qualified. No fallback to clipboard or Snipping Tool.
- GUI settings independently enable PNG save, Agent submission and explicit image clipboard overwrite. Defaults: file save only, no Agent submission, no clipboard output; user chooses a local directory. Flushed `.partial` + atomic hard-link publication uses timestamp/UUID names and never overwrites a file. Filesystems without hard-link support fail visibly. Watcher consumes owned published paths before reconciliation, including file-only output. Restart skips pre-existing files as before.
- Native submit uses existing `ingest`, confirmation preview, auto-consent, pause, immutable Local/Remote binding and hash deduplication. Repeated hotkeys are bounded by the native action guard. Settings/mode changes while acquiring a frame refuse ingestion. Screenshot acquisition never uses clipboard APIs. File-only execution creates no Agent result, and neither acquisition nor file publication reads/writes clipboard content or sequence. If submission is enabled, existing independent result delivery still applies. Exported PNGs remain user files and are not deleted by history cleanup.
- Latest/history text is read from durable successful results without clipboard delivery or mutation. Optional clipboard-text input is an explicit separate action. Rust emits Unicode UTF-16 packets (surrogate pairs in one scalar batch), CRLF/CR normalize to one Enter, and never pastes. No Agent rerun, history insertion, delivery receipt mutation, privilege escalation or automatic retry.
- Input preparation 500–10000 ms, 1–200 characters/s, at most 400000 UTF-8 bytes and 5 minutes. GUI actions allow target selection during preparation; global shortcuts pin the foreground top-level and focused child selected at trigger time. Own-process/no-focus targets refuse. Target changes, modifiers, Esc, cancel and shutdown stop remaining input. Progress means events accepted by Windows, not verified target text. UIPI and applications that ignore Unicode packets may prevent typing; users inspect partial output before retrying.
- Existing native hotkey transaction/rollback and exit cleanup cover capture, type-latest and stop-typing. Bindings start disabled. Existing copy/paste, Smart/Always/manual, retry, one Worker slot and Remote outbox are unchanged.

## Boundaries

Region overlay is the next small capture enhancement, after physical monitor/DPI acceptance. No editor, React migration, provider failover, mobile push or additional infrastructure. Linux Worker is design-only: [M12-V](M12_V_PLAN.md). Tests and genuine physical observations remain separate in [validation](M11_X_VALIDATION.md).
