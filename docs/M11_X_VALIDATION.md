## Failures found and corrected

- Operator reported that the first extracted EXE window briefly rendered, then became blank, while another instance could show content. The new typing runtime derived `Default` for a JSON value, producing `typing: null` in the first native snapshot; Vue then read `typing.active` without guarding null. A regression using that actual native envelope failed before the fix and passed afterward. The runtime now starts with an explicit idle object and Vue safely handles null as well. Browser fixtures now include native runtime state on every snapshot. The `1.1.0-dev.3` candidate also adds an actual packaged/extracted WebView gate (`--staging --ui-smoke`): eight consecutive polls must find the hydrated app and visible enabled capture/typing controls. IPC/tray-only smoke was insufficient to detect this defect. Exact final CI/package results belong to the PR handoff; no physical visual PASS is inferred from the DOM gate.

- Baseline main `83a88bc` package run [40088149398](https://github.com/blooddrunk/Shot2Agent/actions/runs/40088149398) failed when the read-only RemoteSigned negative-control process exceeded its 10s cold-start budget. The isolated smoke now permits 30s and still requires exact refusal and successful bypass-scoped read-only validation; production policy/timeouts are unchanged. Green candidate confirms both conditions.
- Initial lint failed on an unqualified test global, then passed after correction. Initial Vue iterations failed on ephemeral native fixture state, a status/region locator, a duplicated label substring and the old 5-action count. All 36 tests now pass with 8 configured actions and persistent simulated native state.
- Real hosted WGC acceptance in [40089811969](https://github.com/blooddrunk/Shot2Agent/actions/runs/40089811969) and [40090175706](https://github.com/blooddrunk/Shot2Agent/actions/runs/40090175706) exposed an access violation on a second apartment. Factories are now explicitly scoped to each capture rather than using process-wide projected static caches across RoUninitialize. Same-thread and cross-thread repeated real captures passed at `9e3105d` and again at `254272c`.
- `9e3105d` then exposed `OFFLINE_TRAY_NOT_PUBLISHED`: new stop/capture menu fields were absent from the offline presentation. Defaults and boolean projection are now aligned; native packaged/extracted tray smoke verifies all new entries and offline publication. Intermediate capture files additionally use Windows delete-on-close, with native read/drop cleanup coverage.
- Final `e76bdb4` Windows/Node 22 matrix exposed one old retry-count case coupled to a 500ms wall-clock budget under slow hosted SQLite writes (1 attempt instead of 2). Like the adjacent retry-exhaustion tests, the successful-retry/restart case now injects a controlled monotonic clock. Independent real budget/expiry tests remain intact; no production retry policy or deadline is relaxed. Final rerun evidence is in the PR handoff.
- `a100c44` then caught a rarer capture teardown access violation after two complete frames, before a new worker thread initialized. Scoped factories alone were insufficient. The capture runtime now owns a lazy `CoIncrementMTAUsage` lease across all shots, serializes capture/shutdown, and decrements only after capture has stopped at app shutdown. The explicit native gate requires three fresh-process rounds, each with 25 real captures across serial/fresh threads plus Unicode readback; any failure fails the gate. This stress result must be checked on the final HEAD; older green runs do not qualify the revised lifetime code.

Tests use disposable roots, synthetic pixels/text, Fake/mock and temporary credentials. No production Token, operator history, personal screenshot or paid model request was used. ## Small physical Windows procedure

Use only the complete candidate ZIP from successful Windows CI, verify its BUILD/MANIFEST SHA. Full extraction, then `Start acceptance.cmd` opens a fresh disposable Fake root; never add a real Agent. Use a new empty temporary PNG output directory. Fake does not call models. The staging app initially contains one unrelated synthetic preview; discard it before A. Clipboard result delivery = manual; save/notifications off. All data below is synthetic.

### A. Monitor screenshot / file-only / one task

1. Use an isolated test desktop/monitor showing only synthetic content (e.g. a full-screen Notepad displaying `M11 capture 中文 123`); copy `M11 clipboard sentinel` to clipboard. Settings → 原生截图与直接输入: refresh displays, select the intended one, choose temporary directory, enable only PNG save. Save settings. Under shortcuts set 截取所选显示器 to an unused Ctrl+Alt+S, save, hide window.
2. Press shortcut once. Inspect one complete PNG in Explorer and open it. PASS: correct monitor/content, actual monitor pixel dimensions including a 4K or mixed-DPI monitor if available, no partial PNG; paste sentinel into a second Notepad and confirm unchanged. Record display layout/scaling, filename/dimensions, observed text and candidate SHA. Clipboard byte/sequence preservation additionally uses the automated native API gate where available; visual paste alone does not prove all formats.
3. In settings enable watching that same screenshot directory, leave submission in confirmation mode, enable “同时交给所选 Agent”. Capture: PASS = one preview and zero task before clicking 提交图片; after click one task/result. Repeat with explicit auto-consent/auto mode: PASS = one task per new synthetic screen, no second watched-file task. Paused capture must refuse. Repeat shortcut while capture busy must not overlap. Do not interpret byte-identical screenshots inside the existing dedupe window as separate tasks.
4. Record missing monitor/DPI/permission cases as NOT VERIFIED. Restore manual/confirm and pause as needed; exit from tray and remove only the disposable root/output directory. Exported files are not removed by app history cleanup.

### B. Direct typing without copy

1. With the same Fake root and manual clipboard delivery, submit a synthetic PNG and wait for its Fake result. Fake output must contain synthetic mixed text; the packaged staging fixture includes Chinese, ASCII, symbols, multiline Markdown, code fences and supplementary-plane characters. 2. From history click 输入此结果 and, within the configured preparation interval, switch to Notepad and click its empty text area. PASS: expected mixed text/line breaks, no extra Agent attempt/history row, sentinel still pastes in another empty document. Test 输入最新结果 via configured shortcut while Notepad already has focus: no app activation, correct latest result. These are physical target-text observations; status “已发送” alone does not prove rendering.
3. At low speed start again; press Esc partway. Then start again and change focus to another window. Injection failure must show an error, never replay/paste or claim verified text. No privilege elevation; administrator/protected targets and applications ignoring Unicode remain limitations.

## Release assessment

### Follow-up: historical screenshots and Chinese typing report

The operator subsequently reported Chinese text rendered as boxes in Windows Notepad on computer A while using Relay, with browser input working, and requested a controllable new-files-only watcher. The operator then identified the target's English input method as the cause. A new preflight checks the selected Notepad window/target-thread English layout when the text contains Han characters, stopping before any key packet with a Chinese-language recovery message. It never changes keyboard layout; browser targets and ASCII-only Notepad text remain allowed. The operator observation qualifies the reported workaround, not an agent-observed physical retest of the new preflight. The existing hosted Unicode EDIT readback is narrower evidence. A local synthetic Notepad document was opened for diagnosis, but no production typing test was submitted before the operator clarified the cause; other Notepad documents were untouched.

Google search input also showed focus changes. Original newline handling sends Enter, which can submit a search/form; this is a plausible explanation, not a captured browser trace. The optional persisted `newlineAsSpace` control normalizes CRLF/CR/LF to spaces for latest/history/clipboard input without sending Enter. Legacy settings retain multiline behavior. Rust tests cover layout classification, allowed browser/ASCII/Chinese layouts, supplementary Han, normalization and no Enter packets; native hosted acceptance additionally reads back flattened mixed Unicode text with unchanged clipboard. No universal browser DOM focus guarantee is inferred.

The watcher originally consumed the initial directory snapshot, but a later stamp change made those historical paths eligible again. A regression reproduces this before the fix. The default/legacy-unset `folderNewFilesOnly=true` now retains ignored baseline and accepted paths until observed deletion; modifications/overwrites cannot enqueue them again. GUI opt-out explicitly includes existing images and modifications with an automatic-task warning. Tests cover initial-content changes, stable new files, repeated edits, delete/recreate, opt-out, settings validation/persistence, restart/resume and GUI default/warning. Independent same-directory native save/direct-submit tests retain file-only zero tasks and one-task submission. Previously submitted tasks are untouched.
