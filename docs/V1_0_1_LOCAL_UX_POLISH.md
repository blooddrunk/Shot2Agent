## 目标与范围

在下一次 Remote/Relay 开发前，用**一个集中实现 PR**改善 Local 单机产品的状态透明度、后台交互与常见误操作，目标版本 1.0.1。保留 Vue/Tauri/Node 结构和现有本机 Agent、不可变任务绑定、截图授权、凭据、Core、投递与文件剪贴板合同。不迁移 React，不增加后端、Relay、遥测、自动 Agent 重跑、自动升级器、托盘新服务或繁琐 Profile 门禁。既有通过且未改动的原生验收不应重复要求。

### P0：Windows 托盘状态清晰、可靠、低打扰

当前事实（apps/desktop/src-tauri/src/main.rs）：启动时绘制单个固定 32x32 RGBA 图标；后续每 2 秒只刷新 tooltip，拼接未本地化的 snapshot.status 和 lastAction.status；暂停、恢复两个菜单项同时存在且始终可用。控制器（packages/desktop/src/controller.ts）的顶层 status 描述**捕获状态**，不是任务执行状态；activity.running / queued、pending、settings、folderError 等已在 snapshot 中。

要求：

1. 提取纯函数把现有 snapshot 派生为共享的 TrayViewState（状态、图标 ID、本地化短文案、详述、可用操作）。不修改已有持久化 schema，也不要将状态写入数据库。优先复用已有快照字段；如确有必要，只补充最小派生字段。
2. 提供离线打包、轮廓可识别的 16/20/24/32px 图标资源或等效原生图像。图标不只用颜色区分，兼容 Windows 11 浅色/深色任务栏与 DPI 缩放；无需在托盘持续旋转动画。视觉状态至少：运行监听、暂停、等待确认、排队/处理中、关闭监听/待配置、异常。
3. 避免混淆两个维度：暂停捕获不停止已有任务；关闭监听也允许手动提交后继续处理。主图标优先级建议：连接/Worker 异常 > 正在执行 > 已排队 > 待确认 > 捕获暂停 > 正在监听 > 关闭/待配置。tooltip 同时说明捕获和任务两者；例如“处理中 1 项 · 排队 2 项 · 捕获已暂停”。
4. “等待确认”只在 pending 真实存在时显示，托盘点击可打开现有预览，但**不要因截图事件主动弹窗或抢焦点**。同一张图片是否提交仍按 confirm / auto 既有规则；不因视觉优化改变上传授权。
5. 托盘菜单只提供当前适用的“暂停截图监听”或“恢复截图监听”，而不是同时提供两个互斥的可执行选项；捕获未启用时不能伪装为“正在捕获”。复制最新结果、重试投递、切换助手和提交当前图片等操作，尽量根据现有资格判断禁用不可用项，失败时有可见、可操作反馈，避免静默失败。
6. 托盘菜单、tooltip 和状态提示使用简洁中文。按钮文案保留普通用户理解的操作，不在界面暴露 worker_error、succeeded 等内部枚举。GUI 首页、侧栏与托盘状态必须取同一个快照语义，避免互相矛盾。
7. 快速动作后即时刷新；后台可采用原有约 2 秒轮询做兜底，但**只在呈现状态变化时更新原生 icon/menu/tooltip**。确保应用退出、协调器失联或 Explorer 托盘恢复时不会长时间假报“正常监听”；资源释放无泄漏；保留关闭窗口后继续工作和托盘菜单彻底退出。
8. 原生图标/菜单的最终 API 与线程用法以当前 Tauri 2 API 核实为准，不靠 Vue 的后台定时器维持状态。

建议状态矩阵（均需覆盖）：

| 现有真实条件 | 主视觉 | tooltip / 行为要点 |
| --- | --- | --- |
| setupRequired=true | 待设置/灰 | 尚未配置 AI 助手 |
| 捕获 off，running=queued=0 | 空闲/灰 | 捕获未开启；手动提交仍可使用 |
| 正常 monitoring | 捕获/绿 | 正在监听（剪贴板/文件夹按实际来源） |
| pending 非空、running=0 | 待确认/琥珀 | 一张截图等待确认；点击打开预览 |
| paused 且没有待处理任务 | 暂停/琥珀 | 已暂停；恢复不补处理旧图片 |
| queued>0 且 running=0 | 排队/蓝 | 排队数量，不误报处理服务空闲 |
| running>0 | 处理/蓝 | 处理及排队数量；如果 paused，明确标明捕获仍暂停 |
| capture_error / worker_error | 异常/红 | 中文原因和恢复入口/重新打开提示 |
| coordinator RPC 不可达 | 异常/红 | 不能继续沿用上一次“正在监听”的图标/文字 |

### P1：同轮完成的低风险 UX 优化

1. 历史任务的“重试结果投递”现在对所有 succeeded 任务都显示（apps/desktop/src/App.vue），但 packages/desktop/src/actions.ts 已有 retryableDelivery / retryableChannels 判断。补充 snapshot 每任务的只读资格，**仅在真正存在可重试的失败通道时显示/启用**；明确“只重新复制/保存，不重新请求 AI”。保留 conflict/ambiguous 等不可盲目重试的边界。
2. 截图预览确认、处理中、已成功但输出失败、Worker/捕获异常的反馈要能直接回答“现在怎样、会不会额外收费、下一步点哪里”。复用现有反馈区域和历史记录，避免新建冗余常驻面板或弹窗。
3. 新增 AI 助手目前硬编码默认 GLM（apps/desktop/src/App.vue 的 addProfile），即使用户用 Codex。选择更合理的初始项：已发现的兼容安装优先，无法确定时让用户清楚选择 Codex / Claude Code / GLM；不得静默变更已保存默认助手，GLM Token 保存仍本地且测试连接可选。
4. 面向普通用户精简可见措辞。尤其 Windows 托盘英文动作、部分 CLI/Agent/Smart/Always 术语和历史原始错误代码。文案保留技术细节的可展开位置，但常态页面先说清楚含义、影响、恢复办法。不要隐藏真正失败或通过虚构“成功”改善外观。
5. 减少不必要的重复 UI，保持现有四页、清晰主次操作、浅色/深色、720px 最小窗口和较窄视口下的可读性。仅修复确认有证据的对齐/密度/焦点问题，不做无证据的大面积重绘。

## 自动化验证（优先）

- 从最新 origin/main 创建实现分支，不覆盖未提交工作。冻结依赖安装；执行 npm run check、npm run desktop:test-ui，以及现有 Rust fmt/test、Windows desktop build/package、解压 ZIP 与 staging smoke；所有失败先修复或显式记录，不能声称 PASS。
- 为 TrayViewState 写确定性的表驱动状态矩阵测试，覆盖 pause+running、off+running、pending、queue-only、正常监控、双通道捕获、错误优先级、协调器离线和瞬时状态抖动；断言状态变化才触发资源更新，不因轮询造成重复图标更新。
- 对菜单资格/暂停切换、语言映射、托盘指令失败与恢复增加受控状态测试，确保失败不会静默报告成功；托盘动作应保持当前线程/IPC/热键/退出行为。
- Vue/controller Fake/mock E2E 覆盖待确认、处理中、暂停仍处理、真正可重试与不可重试投递、首次选择助手、错误文本、键盘/焦点、浅色深色、1040/720/480 宽度。用合成截图和隔离数据目录，**禁止真实 Token、私人截图/历史、付费模型请求**。
- Windows CI 尽可能自动检验原生资源能加载，图标状态映射和菜单操作有效，打包后 runtime、manifest、可执行文件及现有剪贴板回归不变。Playwright 不能拍到真实 Windows 托盘时不得把 DOM 截图当作原生托盘证据。
- 记录每条命令、退出码、测试数量、源 SHA、CI URL 和失败边界；审查开始时仅能引用已执行的 v1.0.0 证据，不能把拟执行的 1.0.1 检查写成已通过。

## 唯一可能需要的操作员验收：真实 Windows 托盘外观

如实现 Agent 没有可操作真实 Windows 桌面的工具，请明确标注“原生托盘可视验收未完成”，并提供这个**最短且精确**的手工流程；不要让操作员重新执行已经通过、且未改动的剪贴板 / 真实付费模型验收。

前提：用 CI 发布的完整 ZIP 解压到独立目录；先退出已运行实例。使用包内隔离 Fake acceptance 启动方式与合成图片，不加载日常真实数据、Token、历史。若 Fake 执行过快，测试端提供仅 staging 生效的可控约 5 秒延迟，不改正式运行速度和队列合同。

1. 启动隔离版；检查托盘“待设置/未启用”状态与中文 tooltip。按界面启动剪贴板确认捕获并应用，托盘变“正在监听”。
2. 在其他窗口用 Win+Shift+S 截一张无私人信息的图；保持原窗口前台，托盘变“等待确认”，不弹窗抢焦点。通过托盘打开应用，确认预览与原有确认提交一致。
3. 用 Fake 提交任务并使其运行至少约 5 秒；观察处理状态，暂停捕获期间图标仍显示处理，tooltip 同时显示暂停；完成后准确恢复捕获/空闲状态。再验证排队数与实际一致。
4. 暂停/恢复托盘菜单互斥、禁用不适用动作；检查深浅任务栏下小图标轮廓与文案辨识，关闭窗口后状态仍刷新。
5. 用隔离测试注入协调器/捕获错误，托盘显示异常而非继续绿灯；菜单打开窗口后可见可恢复的错误。完全退出后托盘图标消失。
6. 若无法自动执行 Win11 Explorer 重启 / DPI 缩放测试，可将其列为“未验证原生环境组合”，附准确重现步骤与预期，不假造自动覆盖。**所有操作都限定在隔离 Fake 环境**。

验收记录必须区分“源码/单测/Windows CI/原生托盘实见/无法验证”，不得笼统写“证据未完整记录”。若原生外观尚未验收，只合并可验证的实现 PR，不发布新的正式 1.0.1 标签。最多一轮基于具体失败的稳定性修复。

## 完成定义

1. 当前使用者不用打开主窗口就能读懂“监听 / 暂停 / 待确认 / 排队 / 处理 / 故障”的区别；暂停状态和任务执行不会互相覆盖或误导。
2. 无效投递重试不再诱导点击，新手不会被默认 GLM 引导误入 Token 表单，文案和错误恢复方式比 1.0.0 明显清楚。
3. 所有改动通过可重复自动验证，原生可视边界独立标记且只请求必要的短手工步骤；不破坏 1.0.0 已通过的本机任务、文件复制、热键及历史。
4. 在实现 PR 的描述中列出有证据的前后对比与完成/未完成项；下一阶段才重新评估 Remote/Relay。
