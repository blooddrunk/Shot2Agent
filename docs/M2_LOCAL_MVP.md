# M2-L: Local-first runnable MVP (2026-10-20)

Status: **Local CLI implementation delivered for review; Windows interactive MVP acceptance pending**. See [usage and manual checklist](LOCAL_MVP_USAGE.md) and [executed verification](M2_VALIDATION.md). M1 is merged as PR #1 (squash commit `2a96212bf15005746f3ee7ef4d170a4c738a88c9`). This document supersedes the *ordering* (not the eventual product scope) of M2–M5 in ROADMAP.md. The target is **one coding-agent development round for an executable Local MVP**, then **one short stabilization/release round if needed**. Remote/VPS/push/full batch editor are deferred.

## User-visible MVP acceptance

On one logged-in Windows 11 PC, with **no Relay, server process, VPS config, or Relay task traffic**:
1. Start from a documented command or minimal launcher; keep an interactive user-session capture receiver running in the background **without stealing foreground focus**.
2. Copy an actual PNG/DIB/bitmap screenshot to the Windows clipboard. The receiver notices a **new image** (not its own result write), offers a visible submit/confirm action by default; explicit opt-in automatic submission may be supported if cheap. A non-image clipboard entry creates no task. Provide a manual **submit current clipboard image** command as a robust fallback if clipboard change monitoring is unreliable.
3. Submitted image reaches the existing shared Local SQLite core with a stable task ID; persisted history/status survive restart. A single same-PC Worker consumes it with an approved read-only Codex Profile. A deterministic Fake adapter remains selectable for CI and offline smoke tests.
4. A real Codex image task returns Markdown/summary to local task history. Result actions: **Copy text**, **Save Markdown to configurable safe directory**; automatic clipboard return mode `smart` is opt-in. For this MVP, `manual` copy must work, and `smart` should be attempted with a testable clipboard-version gate. File clipboard payload is **deferred** unless implemented with verified CF_HDROP and stable local files; normal Markdown local save is sufficient.
5. Both save and clipboard may be enabled together; their outcome/status/retries are separate and do not mutate `task.status`. All optional delivery channels may be disabled (history only). A new user clipboard entry after submission must **not** be overwritten in `smart` mode; `always` must be explicit opt-in only.
6. User sees task ID, queued/running/succeeded/failed/execution_unknown, Markdown result, and recovery instructions. An initial CLI + small Windows helper/tray is acceptable; a complete Tauri/Vue3 GUI and installer are **not** MVP prerequisites. Prefer a small Node coordinator using existing packages plus a narrowly scoped Windows clipboard helper; avoid adding two independent orchestration services.

## Architecture and priority

Re-use M1 `openCore`, `runOnce`, `AgentAdapter`, `TaskView`; do not rewrite SQLite or route Local work through HTTP. Separate (a) Windows interactive clipboard capture/write adapter, (b) Local CLI/coordinator with bounded single-worker processing, (c) Codex subprocess adapter, and (d) idempotent delivery state tracking. Worker-owned Profile registry specifies exact approved workspace, prompt and read-only sandbox; screenshots/text are **untrusted task data**, not executable instructions. Launch Codex via `spawn` with argument array, `shell:false`, strict sandbox, bounded timeout, bounded stdout/stderr and clear execution_unknown semantics; never use unsafe/full-access fallback. Verify CLI flags against the installed Codex version, including supported image attachment and final-output mechanism; handle unavailable/unauthenticated Codex as an actionable failure while Fake still works.

Focus order: **(1) Local Codex + real screenshot file via CLI; (2) Windows clipboard image intake and manual result copy; (3) smart clipboard + independent local save; (4) convenience background watcher/status.** Make each step independently demonstrable. Do not require an installer, full UI, notifications, Remote parity, VPS, or provider account other than Codex for this goal.

Use Windows system clipboard version/sequence where available and retain a submission-time baseline; own clipboard writes must not re-trigger uploads. Clipboard ownership changes or contention => `blocked_by_clipboard_change`, never overwrite in smart mode. Do not clear/replace clipboard when image read fails. Avoid polling clipboard pixel data continuously; poll a sequence number or use a message listener and debounce/retry transient locks. Native Windows integration must execute in an interactive desktop user session, not a service.

## Image resource policy (replaces M1 provisional 16 MP decoder cap in the next implementation)

4K UHD is 3840 x 2160 = **8,294,400 pixels** (accepted by M1). Two side-by-side 4K screens form 7680 x 2160 = **16,588,800 pixels** (rejected at 16 MP). Thus **do not retain the 16 MP hard cap**. Suggested V1 default: **64 million decoded pixels per still image**, with dimension sanity limits, single-frame only, decoder protections, bounded input bytes (20 MiB/image; 60 MiB/task) and task count (20), and bounded concurrency; benchmark real multi-monitor Windows captures and revise if necessary. A 64 MP RGBA decode may cost ~256 MiB before intermediate buffers: do not decode batches in parallel and apply memory/process resource limits.

Policy: preserve original dimensions and legibility by default. If clipboard encoding exceeds the byte limit, first try a bounded, **lossless** optimized PNG or lossless WebP conversion (when supported, without introducing silent behavior differences); retain original provenance, record transformed type, dimensions and original-versus-sent hash as appropriate. Do not automatically downscale, crop or lossy-compress text/screenshots. If lossless cannot fit, show actionable oversized-input error and offer an **explicit user-approved** downscale/lossy option later; record quality/dimension changes. Reject decompression bombs early (metadata before full decode), non-still/animated images, corrupt/truncated bytes, insane dimensions and unsupported types. Synchronize server/core and client-side limits and tests. Do not silently truncate to 16 MP.

## Automated verification (mandatory)

- `corepack pnpm install --frozen-lockfile`; `npm run check`; Windows and Linux CI; build/launcher smoke from compiled output.
- Clipboard abstraction tests with injected sequence numbers, mixed image/text, transient clipboard busy, own-result write, double event, new user clipboard copy and concurrent completions. Validate no focus-stealing calls are used.
- Local fresh-root Fake E2E (clipboard synthetic image -> confirm -> durable task -> Worker -> Markdown -> manual copy / atomic save -> restart/history). Assert no Relay import/listener/URL/network task transport. Negative: bad image/hash, oversized decode, inaccessible output directory, duplicate event, failed copy/save, restart during queued task, worker crash after launch => no blind replay.
- Codex adapter tests using **mock executable**, not cloud credentials: exact argv, image paths within owned temp directory, prompt/data separation, read-only enforcement, output parsing, timeout/kill + child reap, nonzero exit, malformed/huge output, cancellation/unknown result and secrets redaction. Real Codex desktop acceptance is separate, do not mislabel mocked tests as live success.
- Image boundary tests: 3840x2160 pass, 7680x2160 pass, 64 MP boundary pass, over cap fail; 20 MiB and 60 MiB enforce; use inexpensive fixtures or synthetic sparse/compressible pixel buffers with explicit resource guard to avoid CI OOM.
- Independent delivery channel fan-out, history-only mode, clipboard conflict, atomic file save, path escape and re-entrance prevention.

## Mandatory limited manual Windows acceptance (only for native integration and real Codex)

Prerequisites: logged-in **Windows 11 interactive desktop**, Node 22.16+ and pnpm 10.19, `codex --version` and authenticated Codex CLI, disposable user-owned workspace, a synthetic image containing known words, temporary output directory **outside watched input directories**, no VPS/Relay config; record actual build SHA and `codex --version`.

1. Run documented install/build and Local launcher; verify visible ready/status without taking focus from Notepad. Keep the app running and record command + exit code if it fails.
2. Copy synthetic screenshot (prefer 3840x2160 where available) to clipboard, trigger confirm/manual submit and record exactly one task ID. With Fake: verify succeeded, result/history and persistence after app restart. Inspect process/network behavior: no Relay configuration or task transport; optional Codex cloud network traffic is expected when real adapter runs.
3. Select approved read-only Codex Profile and submit screenshot with known text. Compare returned Markdown with text; verify no files in read-only workspace modified and no input screenshot/task payload leaked into repository or logs. If Codex is unauthenticated/unavailable, mark **live Codex NOT VERIFIED** with exact failure; Fake proof still valid.
4. Before a result arrives copy a different sentence; verify `smart` preserves it. Click **Copy text** and paste into Notepad; check exact text. Enable save + clipboard together and verify both succeed independently, then force an unwritable save target and verify clipboard/history still work. Disable both and verify history-only mode.
5. Copy text-only/non-image to clipboard; verify no submission. Copy one image twice without a new intended capture; verify debounce/dedupe. Optionally exercise 7680x2160 synthetic multi-monitor image; confirm no 16 MP rejection; record observed memory and result.
6. Exit/relaunch during queued work and while processing. Verify persisted queue; if Agent may have launched before interruption, report `execution_unknown` without automatic replay. Test clipboard contention and repeated result event don't cause upload loops. Confirm no foreground focus theft.
7. Collect a sanitized text acceptance log with each step: **prerequisite, exact commands/actions, expected, observed, PASS/FAIL/NOT VERIFIED**. Never upload user screenshots, tokens or private Codex output as public evidence.

## Exit criterion and development-round budget

M2-L is complete only when a Windows user can actually do **clipboard screenshot -> Local task -> real Codex -> Markdown -> user clipboard**, with Fake mode end-to-end and all automated gates passing. If a Windows interactive desktop or Codex authentication is unavailable to the coding agent, it must finish and test everything automatable, ship an exact manual script/checklist, and label native/live features **unverified**, not claim MVP acceptance. One stabilization pass can fix native integration; later work (Remote/VPS/notifications, batch GUI, file clipboard, installers) must remain a separately scoped round. Don't turn missing optional polish into a new multi-milestone plan.
