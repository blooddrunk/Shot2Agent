## P1 — fix evidenced Local reliability holes with minimal changes

- **Atomic file saving:** `packages/local/src/delivery.ts` performs existence/read validation before `renameSync(temp,target)`. This is a check-then-rename race; a concurrent writer can install a different target between the check and rename, and the rename can replace it on Windows. Use a safe publish-if-absent approach (or transactional coordination + no-clobber primitive) that preserves existing mismatched files. Test conflicting concurrent writers, identical retry, symlink/reparse boundary and save failure while clipboard succeeds. Do not overwrite an operator-owned file.
- **Delivery vs execution:** keep retry receipts independently durable for clipboard and Markdown. Transient `CLIPBOARD_BUSY`/temporary save errors may get bounded, user-configured retry count/backoff/time budget; 0 = no extra attempts. Classify permanent refusal separately. Smart must recheck the **original** baseline for every attempt and stop on changed sequence/session. `blocked_by_clipboard_change` is never retried automatically; manual Copy stays explicit. Avoid timer storms, hidden background replay, or unbounded retries on restart.
- **Agent rerun:** no automatic replay for launched/unknown Codex work (`execution_unknown` or other ambiguous failures). A new explicit rerun UI is optional **only after** it can create a new durable task/attempt lineage without mutating original evidence, pin the approved profile, show extra model cost risk and avoid race with active workers. Otherwise defer rerun, explain the boundary, and deliver the reliability gate without it.
- **Clipboard diagnostics:** distinguish native contention from refusal/conflict and unknown write outcome without collecting contents. WeChat Input Method cross-device clipboard sync is only an operator-observed correlation, **not established cause**. Do not bypass Smart checks with sequence resets, content equivalence assumptions or Always overwrite.

## Implementation (0.4.0)

The bounded M4-L implementation preserves the M3 capture/UI and execution policy. Markdown publication now uses a flushed private temporary file and atomic `link` creation; an existing target is verified for identical bytes or refused. Filesystems without hard-link support fail closed, with no replacement fallback. Output directories must be operator-owned canonical local paths (not links/junctions); concurrent hostile directory replacement by another principal is outside this Local trust boundary.

Delivery accepts optional `retry: { maxRetries, backoffMs, budgetMs }`. Defaults: 0 extra attempts, 100 ms initial exponential backoff capped at 1000 ms, 3000 ms budget. Valid ranges: 0–10, 10–1000 ms, 100–10000 ms. Both channels use independent copies of this policy, reservation, attempt count and time budget. Native clipboard writes receive the remaining deadline; expiry terminates the helper and is ambiguous, never retried. Synchronous filesystem calls cannot be preempted: the budget bounds retry scheduling, not an OS-level stalled filesystem call. No network share guarantee is added.

Only known pre-write `CLIPBOARD_BUSY` and `EBUSY/EAGAIN/EMFILE/ENFILE` save failures retry automatically. Conflict, unsafe path, permissions, disk-full, unsupported filesystem, invalid/unknown errors and ambiguous clipboard outcomes stop. Every Smart attempt uses the original capture session/sequence under the native lock. No refreshed baseline, content-equivalence inference or mode escalation exists. Native write retry loops were removed so the configured count is authoritative; bounded native read contention handling remains. Receipts retain up to 100 failure events, cumulative attempts and a final stop reason. Successful channels are not replayed. A stale `pending` reservation becomes `interrupted/ambiguous` only after acquiring the exclusive Worker; restart never auto-delivers it. Explicit delivery retry is a deliberate user action and never executes an Agent.

Agent rerun UI is deferred. Preflight/aborted-before-launch `failed`, launched failure and `execution_unknown` remain distinct in existing task results. No terminal execution is automatically replayed, including preflight failure. Existing mock Codex and process tests verify these boundaries; real authentication is not inferred.

Only phase/allowlisted error codes are diagnosed: Node launch, parent handshake, coordinator initialization, native helper startup, serving, IPC command and disconnection vs timeout. Clipboard errors distinguish contention, sequence/session refusal and possible post-clear write failure. No clipboard content, third-party attribution, exception text or Agent log is persisted. Windows Job termination is unchanged. EXE smoke now uses a unique temporary root, never the operator's acceptance/history root.

See [M4 validation](M4_VALIDATION.md) for commands and current evidence. WeChat Input Method synchronization remains an observed correlation, not an established defect or universal compatibility claim.
