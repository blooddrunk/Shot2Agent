# 跨设备处理（M10 / 1.1.0-dev.1）

这是开发候选版，不是正式 v1.1.0。Local 仍默认在本机处理，不需要 Relay；Remote 将你提交的截图经私人 VPS 交给另一台电脑上已批准的 Agent。网页版历史、移动推送及自动 Agent 重跑不在本轮范围。自动化与真实设备观察分别记录在 [验证记录](M10_R_VALIDATION.md)。

## 普通使用：A 截图，B 处理

1. 部署人员按 [Relay 部署说明](../deploy/relay/README.md) 准备 HTTPS 地址，以及归属于同一 owner 的两个独立设备 Token。ZIP 中的 `Relay source` 是可复制到 VPS 构建的最小源码上下文；其 `SOURCE.txt` 必须与 ZIP 的 `BUILD.txt` 一致。进入 `Relay source/deploy/relay` 操作。
2. 在 B 正常打开 Shot2Agent.exe，先在 **AI 助手** 添加/选择 Codex、Claude 或 GLM。程序、工作区和权限均由 B 本地批准；A 看不到这些私有设置。
3. B 打开 **设置 → 跨设备处理**，填写 Relay HTTPS 地址、这台电脑的名称和 B 的设备 Token。点 **保存连接**，再点 **测试连接 / 刷新电脑**，看到“Relay 已连接”。勾选 **在本机接收远程任务**。B 无需选择远程目标，新任务处理位置可以继续为 Local；接收角色和截图目标互相独立。设置区显示本机当前可接收的助手。
4. A 打开同一设置区，填写相同 HTTPS 地址和 A 自己的 Token，保存、测试连接。在 **远程电脑及已批准 Agent** 中按电脑名称和设备 ID 找到 B，选择当前助手（不确定时可选标有“对方默认”的助手），把 **新任务处理位置** 切成 Remote。列表隐藏本机、历史版本及已移除配置；按电脑分组并标明在线/暂停/离线。同一名字下不再堆叠旧版本号，选中时仍绑定精确版本。B 更新后刷新即可看到当前配置，旧任务保持原绑定。
5. A 的捕获、确认预览和多图操作与 Local 一样。首页显示远程电脑/Agent。新任务先显示“等待上传”，Relay 确认后进入排队/处理，完成后自动出现在 A 的历史里。B 暂停或离线时任务仍排队。不会转给 A 的本机 Agent。
6. 在 A 的 **结果去向** 独立选择 Markdown 保存、文本/Markdown 文件剪贴板和 Windows 通知；也可全部关闭，仅保留历史。历史里的 **复制文本 / 复制文件** 和失败通道的投递重试使用已有结果，不重新请求 Agent。文件复制使用 A 上已验证、保留的 `.md` 文件，可粘贴到资源管理器。

Token 只保存在 Windows 凭据管理器；设置/快照不包含 Token。换 Token：在原地址重新填入新值，保存、测试连接。删除：点 **删除设备 Token**，会停接收并回到 Local，已有 Remote 队列/历史保留。不要在任务执行中轮换/撤销 B 的 Token；先取消接收，等当前任务结束。

**保存连接**只写本机配置并检查凭据能否读回，不访问 Relay；**测试连接 / 刷新电脑**才校验服务端身份并刷新能力。粘贴内容的首尾空白会自动去掉，Token 中间不能夹有空格或说明文字。保存失败会保留遮蔽的输入，并区分 Token 格式、Windows 凭据管理器写入/读回、设置文件写入错误；修正后再保存。填写了尚未保存的新内容时，先保存，再测试连接。

## 离线、重启与错误恢复

已提交 Remote 图片、原 taskId、目标电脑和 Agent 版本先持久保存在本机私有 outbox，再联网。断网自动重试；重新打开应用后继续原任务。上传确认丢失时仍复用原 UUID/key，Relay 去重。每个条目绑定原 Relay/owner/device；更改地址或设备身份不会把它发送到新连接。要恢复原条目，恢复原地址和设备 Token，再测试连接。

上传的永久拒绝（例如认证/目标冲突、大小不符）会显示错误；修复配置后点 **重试上传 / 同步结果**。连接状态和上次同步时间在设置中，任务行显示处理位置和上传状态。B 的能力可能离线，刷新后重新选择明确的电脑/Agent；不自动替换目标或回退 Local。

B 只向 Relay 发出 HTTPS 请求，同一应用的 Local/Remote 执行共享一个槽。取消接收只阻止下一项远程 claim，已开始的任务继续。开始前丢失租约可安全重新排队；开始后中断显示 `execution_unknown`（执行结果不确定），不会自动再执行。请先在 B 确认进程已停止，再决定是否另行提交新任务，可能产生额外模型费用。

切回 Local 仅影响后续提交；旧 Remote 上传/结果接收继续尝试，所以其仍可有网络活动。没有 Remote 配置、接收角色和待同步任务时，Local 不发任何 Relay 请求。历史清理只移除 A 的本机副本；不删除已导出的 Markdown、当前文件复制缓存或 VPS 记录。Remote 缓存上限 1000 个条目/512 MiB；清理已完成历史可释放其私有图片/附件，缓存复制文件在原有设置区单独清理。

## 最小真实设备验收

先从本 PR 对应成功的 Windows CI 下载完整 ZIP，核对 BUILD/MANIFEST 的 SHA。准备 VPS/域名、A/B 两台 Windows（实际跨网络）及**临时设备 Token**。每台完整解压，打开 **Start Remote acceptance.cmd**：它只在 ZIP 旁的 `Remote acceptance data` 创建可重启的隔离目录，使用 Fake，不读取正常 Shot2Agent 历史，也不请求模型。每台通过本指南第 3–4 步连接。不要在验收窗口添加真实 Agent。以下各项记录 PASS/FAIL、版本/SHA、观察结果；没有观察的保持 NOT VERIFIED。

| 项目 | 实际窗口/操作 | PASS / FAIL 的可观察判定 | 失败恢复与未验证边界 |
| --- | --- | --- | --- |
| 连接与闭环 | B 设置勾选接收；A 设置选 B/Fake、Remote。用画图打开 ZIP 的 Remote synthetic 1.png，Ctrl+A/Ctrl+C；回 A 点“处理剪贴板图片”。再从“添加图片文件…”选 5 张合成 PNG，点下移重排后提交。 | 每次提交只有一条任务；显示等待上传→排队/处理→完成，结果分别显示 1/5 images，A 的普通 Local 数据不变。Token 字段保存后为空。拒绝/无结果/重复为 FAIL。 | 查看设置连接错误，检查 B 接收及目标；测试连接重试同一上传。此项证明实际 Windows GUI/Fake，不能证明真实付费模型能力。 |
| 原生返回 | A 结果去向开启保存与通知，剪贴板先选手动。历史“复制文本”→记事本粘贴；“复制文件”→空 Explorer 文件夹 Ctrl+V，打开 .md。再选 Smart、提交新合成图后复制新文字并等待。 | 保存内容正确；Explorer 得到真实可打开文件；通知不抢焦点（系统允许时可见）；Smart 保留新文字并显示保护状态。仅 API 写入不能算粘贴 PASS。 | 原通道失败不重跑 Agent；检查目录权限/通知设置后手动复制或投递重试。真实 IME/所有系统组合不在此结论中。 |
| 跨网络与恢复 | B 取消接收，A 提交合成任务；B 再勾接收，完成前从托盘退出 A。部署人员重启 Relay；重新打开 A 的同一验收启动器。 | 离线时明确排队；重新连接后只有一个完成结果/一次 attempt；保存及通知不重复。A/B 在实际不同网络通过有效 HTTPS 通信。 | 保留原数据/设备身份，恢复服务并点测试连接。不要对不确定执行重新提交；公网 TLS、VPS 重启需要实际观察，容器 CI 不代替。 |

Token 撤销、丢失确认、过期租约、进程中断与损坏注入由自动化承担，通常不要求人工再执行。完成验收后两端先在 GUI 删除临时 Token，从托盘退出，再删除各自的 `Remote acceptance data`；这不会触碰正常应用数据。部署人员撤销临时设备。此候选版不会自动发布 v1.1.0。
